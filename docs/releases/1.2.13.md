# 1.2.13 — Ctrl+C 이후 지연된 붙여넣기 취소

## 변경 사항

- Ctrl+C 전에 요청한 클립보드 데이터가 늦게 도착해 종료 후 CMD에 붙여넣어질 수 있는 경로를 수정했습니다. 중단 시 이전 시스템 클립보드 읽기 결과와 대기 중인 내부 클립보드 요청을 취소합니다.
- Ctrl+C 자체는 기존 입력 경로로 전달하며, 이후 사용자가 새로 요청한 붙여넣기와 일반 입력은 유지합니다. 이미 ConPTY나 원격 서버에 전달된 입력을 회수하지는 않습니다.
- tail·tcping의 우클릭 유무, Ctrl+C 이후 CMD 복귀, 출력·클립보드 내용의 실행 여부를 기록하는 Windows 진단 검사를 추가했습니다. `resources/`의 사용자 제공 샘플은 Git과 배포에서 제외합니다.

## 검증과 제한

- 2026-10-20 사용자가 수정 개발 빌드의 문제 해결을 확인했습니다. 이 확인은 해당 사용자 환경의 보고이며, 새 버전 배포 EXE의 자동화된 Windows 전체 회귀 검사 통과를 뜻하지 않습니다.
- Linux 호스트 Python 회귀 검사 34개 통과. 패치된 입력 함수와 클립보드 전달 분기로 ETX 전달, 지연된 요청 취소, 새 요청·여러 요청 보존을 검사했습니다.
- Windows x64 교차 빌드·테스트 EXE 컴파일, 단일 EXE ZIP·내장 리소스·시스템 DLL·해시 정적 검사를 수행합니다.
- Linux 환경에서 Windows 샘플·SSH/UI/IME/DPAPI·NGS 실행 검사는 미실행입니다. macOS·iPad와 GitHub Actions는 실행하지 않습니다. 후속 Windows 진단 명령과 범위는 [개발 안내](../development.md#로컬-cmd-ctrlc-재현-검사)를 참고하세요.
