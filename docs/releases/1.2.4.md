# 1.2.4 — 전체 화면 앱의 대화 스크롤

## 변경 사항

- Codex처럼 대체 화면에서 마우스 보고를 요청하는 앱에는 휠을 전달합니다. 이전 대화를 탐색하기 위해 별도의 Codex 실행 옵션을 지정할 필요가 없습니다.
- 기본 복사 우선 모드에서도 드래그 복사·우클릭 붙여넣기를 유지하고, 클릭·드래그·포인터 이동은 앱에 전달하지 않습니다.
- `Shift+휠`은 터미널 기록을 스크롤합니다. 이미 터미널 기록을 보고 있거나, 일반 화면이거나, 앱이 마우스 보고를 요청하지 않은 경우에도 기존 로컬 스크롤을 유지합니다.
- 명시적인 마우스 보고 차단 설정을 존중합니다. 앱이 보고 모드를 해제하지 않고 일반 화면으로 돌아와도 휠은 로컬 스크롤로 복귀합니다.
- 휠 단위 누적과 기존 PuTTY 마우스 인코더를 사용하며, 새 출력의 스크롤 위치 유지·Enter 최신 화면 복귀 정책은 유지합니다.

## 검증과 제한

- Windows x64에서 릴리스 앱과 테스트를 빌드했습니다. 사용 중인 개발용 EXE를 보존하기 위해 `build/native-release-1.2.4`에서 동일한 컴파일러·빌드 옵션을 사용했습니다.
- CTest 4개(launch-relay, sftp-codec, core, ime), Python 도구 테스트 실행 성공(13개 실행, 호스트 C 컴파일러 부재로 1개 건너뜀)을 확인했습니다.
- 새 빌드의 스크롤 검사 4종(기본, follow-output, 명시적 보고 차단, 앱 보고 미요청)과 마우스 검사 3종(기본, 앱 마우스 허용, 대체 화면)을 통과했습니다. 총 410개 UI 조건과 SSH 입력 방향·횟수·누출 여부를 검사합니다.
- 폰트 캐시, 메시지·확인창, 실행 인자·기존 창 전달, 개인키 가져오기와 SSH 인증 검사를 통과했습니다.
- 전체 SSH/UI 통합 검사는 미완료입니다. 첫 실행은 탭 닫기 확인창의 초기 키보드 포커스 검사에서 실패했고, 재실행은 그 검사를 통과한 뒤 phase 34의 실제 마우스 클릭 대상 검사에서 실패했습니다. 자동화 입력 대상 확인 실패를 통과로 표시하지 않습니다. 잠기지 않은 데스크톱에서 입력 간섭 없이 재검증해야 합니다.
- 휠·클립보드 검사는 실제 루프백 SSH와 Win32 메시지를 사용합니다. 모든 앱·마우스 하드웨어의 물리 입력을 검증한 결과는 아닙니다. 수정 개발 빌드의 실제 사용에 대해서는 사용자가 정상 동작을 확인했습니다.
- 단일 EXE ZIP, EXE/ZIP 일치, SHA-256, 내장 리소스, x64 시스템 DLL 의존성을 검증했습니다. manifest에 깨끗한 소스 커밋을 기록했습니다.
- NGS 실기 검사, macOS·iPad 빌드 및 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
