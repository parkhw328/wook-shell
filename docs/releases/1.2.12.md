# 1.2.12 — SFTP 키 재교환 후 전송 재개 보완

## 변경 사항

- 약 2GB 업로드 도중 중간에서 0 KB/s에 머무른다는 보고를 조사했습니다. 기본 SSH 재교환 한도는 1GiB이고, 기존 SFTP 입력 파이프는 `Seat.sent` 알림에만 의존해 재개했습니다. 재교환 후 transport 큐가 알림 이후 비워지면 입력 파이프가 중단된 채 남을 수 있습니다.
- PuTTY Plink와 같이 이벤트 루프의 최상위 콜백 처리 후 실제 송신 대기량을 재확인합니다. 기존 흐름 제어·중복 읽기 방지와 SSH 재교환 설정을 유지합니다. 일반 터미널 입력에는 적용하지 않습니다.
- SFTP 독립 로그인과 서버의 OTP 재사용 금지 정책을 사용법에 설명했습니다. 인증 정책이나 OTP 저장 동작은 변경하지 않았습니다.

## 검증과 제한

- Linux Python 회귀 검사 32개 통과. 실제 파이프 재개 함수와 PuTTY throttle 함수를 호스트에서 실행해 알림 이후 큐 소진 시 재개, 중복 읽기 방지, backlog 제한, 종료·일반 터미널 제외를 검사했습니다.
- Windows 루프백 벤치마크에 `--rekey`를 추가했습니다. 256KiB 재교환 한도로 8MiB 파일의 반복 키 교환과 업로드·다운로드 바이트 일치를 검사합니다. JavaScript 구문 검사 통과.
- Windows x64 교차 빌드·테스트 EXE 컴파일과 배포 ZIP·내장 리소스·시스템 DLL·해시 정적 검사를 수행합니다.
- Linux 환경이므로 실제 Windows SSH/SFTP·2GB 업로드·반복 키 교환 통합 검사는 미실행입니다. 사용자 환경의 원인을 확정하거나 해결을 실증한 결과는 아닙니다. Windows 후속 명령은 `node tests/ssh/sftp-benchmark.cjs --rekey`입니다. macOS·iPad와 GitHub Actions는 실행하지 않습니다.
