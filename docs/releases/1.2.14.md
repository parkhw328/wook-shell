# 1.2.14 — Windows tail·tcping 중단 후 붙여넣기 재실행 수정

## 변경 사항

- Windows 로컬 CMD에서 `tail.exe`·`tcping.exe` 실행 중 우클릭으로 붙여넣은 내용이 Ctrl+C 이후 명령으로 실행되는 문제를 수정했습니다. 사용자가 제공한 두 실행파일과 1.2.13 배포본으로 증상을 재현했습니다.
- 로컬 엔진이 자신의 CMD 콘솔에 연결하고, processed 입력 모드에서 Ctrl+C를 전달하기 전에 아직 읽히지 않은 콘솔 입력을 비웁니다. 1.2.13의 지연된 클립보드 요청 취소에 더해, 이미 ConPTY에 전달된 대기 입력도 처리합니다.
- raw 모드의 문자·ETX, SSH 입력, 중단 후 새 붙여넣기를 유지합니다. 콘솔 제어 신호로 엔진이 종료되지 않게 하고 CMD 종료 시 콘솔 연결을 해제합니다.
- Windows 회귀 검사의 세션 설정 줄바꿈·판정 오류와 SSH 마우스 검사의 Shift 대상 오타를 수정했습니다. Python 호스트 검사는 임시 DLL을 해제한 뒤 정리하도록 보완했습니다. `resources/`의 사용자 샘플은 배포하지 않습니다.

## 검증과 제한

- 로컬 Windows x64에서 소스 커밋 `18f608e`를 변경 없는 상태로 빌드했습니다. 배포 EXE의 파일·제품 버전은 모두 `1.2.14`입니다. 테스트 도구 정리 보완은 이후 커밋 `2d9abe5`이며 제품 코드는 변경하지 않았습니다.
- 배포 EXE로 `python tests/local-interrupt.py --exe release/1.2.14/windows-x64/wShell.exe`를 실행해 최종 13개 사례를 통과했습니다. 두 샘플 각각 우클릭 없음·붙여넣기·즉시 중단·1,000줄·줄바꿈 없는 입력·출력 드래그 복사, raw 입력 보존을 검사했습니다. 중단 후 CMD 복귀·새 붙여넣기·반복 Ctrl+C·정상 종료와 화면 캡처도 확인했습니다.
- CTest 4개(launch-relay, sftp-codec, core, ime), Python 회귀 검사 34개, 폰트 캐시·접속 인자·개인키 인증·대화상자 253개 조건을 통과했습니다.
- SSH 마우스 4개 모드(각 62개 조건)와 스크롤 4개 모드(88/88/81/81개 조건)를 통과했습니다. 일반·대체 화면, 앱 마우스 설정, 출력 추적·보고 차단·보고 미요청 조합을 검사했습니다.
- 초회 실행에서는 우클릭 없는 tail의 다음 명령 앞에 추가 문자 `e`가 나타났고, 앱 마우스 모드의 첫 드래그 복사 검사도 실패했습니다. 같은 바이너리로 로컬 13개 사례와 해당 마우스 모드를 재실행해 통과했습니다. 초회 실패 원인은 확정하지 않았으며 모든 데스크톱 입력 경로의 안정성을 보증하는 결과는 아닙니다.
- 전체 SSH/UI 통합 검사는 phase 34의 실제 클릭 대상 확인(`Native click must hit the test window, never another application`)에서 중단되어 미완료입니다. 입력 대상 확인을 생략하거나 통과로 처리하지 않았습니다. 잠기지 않은 데스크톱에서 입력 간섭 없이 `node tests/ssh/focus-integration.cjs`와 전체 통합 검사를 다시 실행해야 합니다.
- 단일 EXE ZIP·내장 폰트/아이콘/라이선스·x64 시스템 DLL 의존성·SHA-256·전체 배포 목록 무결성 검사를 통과했습니다. EXE와 ZIP 내부 파일의 바이트가 동일합니다.
- NGS 실기 검사, macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
