# 0.14.0 — 추가 접속을 기존 창의 새 탭으로 열기

상태: Windows 개발 빌드. Linux 교차 빌드·정적 패키지 검사를 완료했으며 Windows 실행·NGS 실기 검증은 남아 있습니다. 기존 0.13.0 공개 배포는 유지합니다.

- 명령줄·바로가기·외부 프로그램에서 추가 SSH 접속을 실행하면 기존 창의 새 탭으로 엽니다. 같은 서버를 다시 실행해도 별도 탭을 만듭니다.
- 실행파일 이름은 `wShell.exe`로 유지합니다. 같은 Windows 로그온·권한 수준·데이터 폴더의 창을 재사용하며, 인자 없는 실행은 기존 창을 표시합니다.
- 접속 인자·일회용 암호는 로그온 SID 전용 로컬 Named Pipe로 전달하며 추가 평문 파일·로그·자식 명령줄에 기록하지 않습니다. 전달받은 암호는 기존 DPAPI 일회용 처리로 연결합니다.
- 동시 요청과 시작 중 요청, 큐 포화, 종료 시 취소와 재시작을 다루며 전달 오류 시 자동 재시도로 중복 탭을 만들지 않습니다.

NGS 연동은 선택 사항입니다. 특정 사용자 환경에서는 별도 복사본을 기존 PuTTY 경로에 `putty.exe`로 배치해야 인자가 전달됐습니다. 해당 환경에서만 사용자가 이름을 변경하며, 이름을 바꾼 파일은 별도로 제공하지 않습니다. 자세한 절차는 [README](../../README.md#추가-접속을-기존-창의-새-탭으로-열기-0140-개발-빌드)에 안내합니다. 교체 전 기존 wShell을 종료하고, 실제 두 서버 접속에서 창 하나·탭 두 개·각각의 로그인을 확인해야 합니다.

검증: EXE·IPC 테스트 EXE 교차 컴파일, 단일 EXE ZIP·SHA-256·시스템 DLL 의존성·내장 리소스 검사, Python 도구 회귀 테스트 11개, SSH 테스트 스크립트 구문 검사. Windows IPC·SSH·UI 테스트는 이 Linux 환경에서 실행하지 않았습니다. 개발 산출물은 `build/packages/0.14.0/windows-x64/`에 생성하며 검증 전 `dist/`에 배포하지 않습니다.
