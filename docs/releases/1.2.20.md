# Windows 1.2.20 — 메뉴 여백과 경계선 정리

## 변경 사항

- 상단 메뉴 제목의 좌우 여백을 10→18 논리 픽셀로 넓혔습니다. OS가 고정하는 네이티브 메뉴 높이 안에서 글자가 답답하게 보이지 않도록 공통 보조 글꼴 9pt를 사용합니다. 시스템 전체 메뉴 높이·색상 설정은 바꾸지 않습니다.
- 펼친 메뉴는 본문 11pt를 유지하고 최소 행 높이를 32→38 논리 픽셀로 늘렸습니다. 글자와 단축키, 체크 표시의 간격을 유지하며 DPI에 맞춰 조정합니다.
- 기본 흰 구분선을 좌우 여백이 있는 어두운 회색 1px 선으로 교체했습니다. 메뉴바의 빈 영역과 상하 경계, 해당 메뉴의 팝업 외곽에도 Flexoki 테마를 적용합니다.
- 화면 확인 중 발견한 Alt+F4·Alt+F5·Alt+F7 및 일부 Alt+숫자패드 입력이 메뉴로 처리되는 문제를 수정했습니다. 가상 키 코드와 `WM_SYSCHAR`의 문자 정규화를 분리했습니다.
- README와 [메뉴바 안내](../workspace-menu-bar.md)에 수정된 앱의 작업 공간·Host 메뉴 캡처를 추가했습니다. 이전 스크린샷은 기존 문서의 참조를 위해 보존합니다.

## 검증과 제한

- Linux Python 회귀 검사 **59개 통과**. 실제 공유 C 헤더로 F10·메뉴 문자·AltGr·수정 키와 Alt+기능키·숫자패드 입력의 보존을 검사합니다.
- Windows 앱과 테스트 EXE 교차 빌드, 단일 EXE ZIP·내장 폰트/아이콘/라이선스·시스템 DLL 의존성의 정적 패키지 검사를 통과했습니다. 배포 소스·도구·해시는 [manifest](../../release/1.2.20/manifest.json)에 기록합니다.
- Linux Wine 8.0의 `WOOK_TEST_MENU_STYLE_ONLY=1` **404개 검사 통과**. 메뉴 여백·구분선·메뉴바 빈 영역·프레임 재그리기·팝업 외곽을 확인했습니다. 96·144·192 DPI는 측정·그리기 함수에 입력한 값이며, 실제 모니터 이동 검증이 아닙니다. Wine에서 Host 메뉴를 마우스로 열고 Esc로 취소한 뒤 Alt+F4로 창을 닫는 동작도 확인했습니다.
- README 이미지는 96 DPI의 Wine·Xvfb에서 **실제 EXE를 직접 캡처**한 것입니다. `build/` 아래 격리 데이터와 세 개의 루프백 예시 호스트만 사용했고 서버에 접속하지 않았습니다. 메뉴나 텍스트를 합성하지 않았으며, Windows의 창 장식·폰트 렌더링과 차이가 있을 수 있습니다.
- Windows 실기의 메뉴·키보드·접근성·다중 DPI·SSH·SFTP·IME·DPAPI·CTest와 NGS 검사는 **미실행**입니다. Wine 검사와 캡처를 Windows 실기 통과로 표시하지 않습니다.
- macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.

Windows에서는 `scripts/build.ps1`로 빌드한 뒤 `WOOK_TEST_MENU_STYLE_ONLY=1`을 지정해 `ui-smoke-tests.exe`를 실행하면 스타일 검사를 재현할 수 있습니다. 환경변수를 지운 뒤 기존 `node tests/ssh/connections-integration.cjs`, `node tests/ssh/focus-integration.cjs`, `node tests/ssh/message-integration.cjs`, `node tests/ssh/integration.cjs`로 전체 회귀를 확인합니다.

이번 캡처에만 사용한 Wine은 EPEL의 서명된 8.0-1.el9 RPM을 검증하고 `.tools/` 아래 풀어서 실행했습니다. 제품과 배포 ZIP에는 포함하지 않습니다.
