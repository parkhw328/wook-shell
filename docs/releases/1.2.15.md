# 1.2.15 — Windows·Linux 빌드 조건과 배포 메타데이터 통일

## 용량 차이 조사

| 비교 대상 | EXE 크기 |
| --- | ---: |
| 기존 1.2.13 Linux 배포본 | 4,111,872바이트 |
| 같은 1.2.13 소스의 새 Linux 빌드 | 3,654,656바이트 |
| 1.2.14 소스의 새 Windows 빌드 | 3,657,216바이트 |
| 같은 1.2.14 소스의 새 Linux 빌드 | 3,654,656바이트 |

동일 소스를 SHA-256으로 고정된 LLVM-MinGW·CMake·Ninja로 빌드한 결과, Windows와 Linux의 실행 코드·읽기 전용 데이터·전역 데이터·예외 처리·재배치 섹션이 바이트까지 일치했습니다. 컴파일러는 양쪽 모두 Clang 23.1.2이며 정적 C++/MinGW 런타임 라이브러리도 동일했습니다. 남은 2,560바이트 차이는 내장 라이선스의 CRLF/LF 차이 2,377바이트, 앱 manifest의 줄바꿈 차이 19바이트와 리소스·PE 정렬에서 발생했습니다. 라이선스 파일의 대소문자 정렬 순서도 호스트별로 달라 파일 해시에 영향을 주었습니다.

기존 1.2.13 배포본과 같은 소스 커밋 `e0277c0`의 재빌드 차이는 457,216바이트입니다. 당시 컴파일러·캐시·환경 옵션이 기록되어 있지 않아 특정 원인을 확정할 수 없습니다. 큰 차이를 Linux 자체의 필수 비용으로 설명할 수 없으며, 기존 공개 파일과 알려진 출처는 보존합니다.

## 변경 사항

- 두 빌드 진입점이 `scripts/windows-release.cmake`의 동일한 Release 설정을 사용합니다. 이전 캐시·환경 옵션에 의한 설정 편차를 제거하며 기존 `-O3`, 정적 런타임과 Windows 보호 옵션을 유지합니다. PuTTY의 C assertion과 암호 연산 최적화 경계를 유지합니다.
- 내장 라이선스 고지를 UTF-8/LF와 명시적인 파일명 정렬 순서로 생성합니다. 앱 manifest·버전 헤더도 LF로 생성하고 PE 타임스탬프를 0으로 고정합니다. ZIP 항목의 날짜·속성도 고정해 빌드 시각과 호스트 파일 권한이 패키지에 섞이지 않게 했습니다. 앱 기능·폰트·아이콘을 제거하거나 실행파일 압축기를 사용하지 않습니다.
- 빌드 도구 버전·설정 옵션·정적 런타임 해시·EXE 해시를 기록하고 배포 manifest에 포함합니다. 소스 커밋·변경 상태·버전·EXE가 다른 오래된 기록은 거부합니다. 배포 목록 갱신은 기존 정보를 보존합니다.
- Linux 교차 빌드에도 로컬 raw 입력 회귀 검사 도구를 컴파일합니다. Windows 실행 검사는 Windows에서 수행합니다.

## 최종 산출물 비교

소스 커밋 `cf0292510b52a06f88e354bb7ce889ce3d9aefce`를 변경 없는 별도 checkout에서 Windows 네이티브·Linux 교차 빌드했습니다. 양쪽 모두 LLVM-MinGW 20260922, CMake 4.4.4, Ninja 1.13.2를 사용했습니다.

| 빌드 호스트 | EXE 크기 | ZIP 크기 |
| --- | ---: | ---: |
| Windows | 3,654,656바이트 | 1,661,513바이트 |
| Linux | 3,654,656바이트 | 1,662,756바이트 |

두 EXE는 전체 바이트와 SHA-256 `3d44bacc4c17cff3e150746453af6be59893976840e9f60310361e6069bdfdd7`이 일치합니다. 1.2.14 Windows 배포본보다 2,560바이트 작습니다. 공개하는 파일은 Windows에서 만든 산출물입니다.

ZIP 내부 EXE·항목 이름·날짜·속성은 동일하며, 압축 데이터에서만 1,243바이트 차이가 납니다. Windows의 Python 3.14.7은 zlib `1.3.1.zlib-ng`, Linux의 Python 3.13.16은 zlib `1.2.13`을 사용했습니다. ZIP 전체 바이트의 호스트 간 일치는 보장하지 않습니다.

## 검증과 제한

- Windows Python 검사 39개, Linux 배포 도구 검사 10개와 빌드 정책 검사 3개를 통과했습니다. 다른 시각의 같은 EXE를 ZIP으로 묶었을 때 바이트 일치, 오래된 CMake 캐시 교정, 고지 파일 정렬·줄바꿈 통일, 다른 소스·EXE의 빌드 정보 거부와 기존 manifest 보존을 포함합니다.
- Windows CTest 4개(launch-relay, sftp-codec, core, ime)를 통과했습니다. Linux에서는 Windows 테스트 실행파일을 컴파일하고 패키지를 정적으로 검사했으며 Windows 프로그램을 실행하지 않았습니다.
- 배포 EXE로 `python tests/local-interrupt.py --exe release/1.2.15/windows-x64/wShell.exe`의 13개 사례를 통과했습니다. 사용자 제공 `tail.exe`·`tcping.exe`의 우클릭 붙여넣기·출력 드래그 복사 후 Ctrl+C, 대량·줄바꿈 없는 입력, raw 입력 보존, 새 붙여넣기와 정상 종료를 검사했습니다.
- 폰트 캐시·접속 인자·개인키 인증·대화상자 253개 조건, SSH 마우스 4개 모드(각 62개 조건)와 스크롤 4개 모드(88/88/81/81개 조건)를 통과했습니다. 로컬 중단 후 화면 캡처도 확인했습니다.
- 단일 EXE ZIP·내장 폰트/아이콘/라이선스·앱 manifest·x64 시스템 DLL 의존성·SHA-256 검사를 통과했습니다. EXE의 파일·제품 버전은 모두 `1.2.15`입니다.
- 전체 SSH/UI 통합 검사는 phase 34의 실제 클릭 대상 확인(`Native click must hit the test window, never another application`)에서 중단되어 미완료입니다. 입력 대상 확인을 생략하거나 통과로 처리하지 않았습니다. 잠기지 않은 데스크톱에서 입력 간섭 없이 `node tests/ssh/focus-integration.cjs`와 전체 통합 검사를 다시 실행해야 합니다.
- NGS 실기 검사, macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
