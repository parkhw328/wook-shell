# 1.2.9 — Ctrl+C 이후 좌표 보고와 SFTP 전송 취소·크기 표시 개선

## 변경 사항

- `51;66;13M51;66;12M51;65;12M` 보고를 바탕으로 Ctrl 키가 포함된 마우스 이동 보고 경로를 재점검했습니다. 기존 정리는 대체 화면 종료에 의존해 일반 화면에서 중단하거나 화면 복귀 없이 종료하는 경우를 다루지 못했습니다. 이제 바이트·유니코드 키 입력의 단일 Ctrl+C(ETX)에서 마우스 보고·버튼·좌표 상태를 정리하고 Ctrl+C 자체는 그대로 전달합니다. 앱이 명시적으로 마우스 보고를 다시 켜면 재개합니다.
- Ctrl+C가 앱 종료가 아닌 작업 취소로 사용된 경우에도 재요청 전까지 앱 마우스 입력은 중단됩니다. 이미 전송된 좌표나 화면의 사용자 문자열을 삭제하지 않습니다. 기본 드래그 복사·우클릭 붙여넣기는 유지합니다.
- 기존 상단의 작은 Cancel 버튼을 하단 진행 표시 옆의 **Cancel transfer**로 옮기고 이름·툴팁·진행 영역을 정리했습니다. 취소 중 **Cancelling…** 표시와 중복 요청 차단, 완료 후 **Reconnect (F5)** 안내를 추가했습니다. 해당 SFTP 연결을 종료해 전송 대기 I/O와 배치의 다음 파일을 중단합니다.
- 취소는 이미 완료한 파일을 되돌리지 않습니다. 중단 다운로드의 로컬 임시 파일을 정리하고 최종 대상 교체 전에도 취소를 확인합니다. 업로드의 원격 `.wshell-*.part` 파일은 남을 수 있습니다. 다른 탭은 종료하지 않습니다.
- 양쪽 파일 목록과 전송 진행의 바이트를 `67,108,864`처럼 천 단위 콤마로 표시하고 크기 열을 넓혔습니다. 정수 포맷터는 uint64 최댓값까지 정밀도를 보존합니다.

## 검증과 제한

- Linux Python 회귀 검사 27개 통과. 실제 패치된 키 입력 진입 코드에서 Ctrl+C 정리·다른 키와 여러 문자 입력 보존을 검사하고, 크기 포맷터의 0·경계·4GB·uint64 최댓값을 검증했습니다.
- 마우스 SSH/UI 검사에 화면 전환 없는 Ctrl+C, Ctrl 키를 누른 포인터 이동, 원격 명시적 재활성화, 좌표처럼 보이는 실제 사용자 문자열 보존을 추가했습니다.
- SFTP SSH/UI 검사에 지연된 64MB 업로드·다운로드의 실제 버튼 취소, 하단 버튼 위치·활성 상태, 대기 파일 중단, 로컬 임시 파일 제거, 동일 탭 재연결과 후속 다운로드 및 양쪽 파일 크기·진행 바이트 표시를 추가했습니다. JavaScript 구문 검사 통과.
- Windows x64 교차 빌드·테스트 EXE 컴파일 및 단일 EXE ZIP·내장 리소스·시스템 DLL·해시 정적 검사를 수행합니다. 배포 manifest에는 커밋된 소스와 Linux 교차 빌드 출처를 기록합니다.
- Windows 데스크톱이 없어 Windows 자동 테스트·실제 Codex 재현·SFTP 취소 실기·UI 화면 캡처 검사는 미실행입니다. 사용자 환경에서 보고된 증상이 해결됐다고 확인받은 것은 아닙니다. macOS·iPad 빌드와 GitHub Actions도 실행하지 않습니다.

Windows 후속 검사와 명령은 [개발 안내](../development.md#129-검증-인계), 기능 사용법은 [SFTP 안내](../sftp.md)를 참고하세요.
