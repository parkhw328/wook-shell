# 1.2.18 — 공개키 파일로 로컬 접속 키 선택

## 변경 사항

- 호스트 저장·접속, Host Settings와 SSH 키 관리자에서 OpenSSH/RFC4716 공개키 파일을 선택할 수 있습니다. 등록된 키 목록과 같은 폴더에서 실제 공개키 내용이 일치하는 개인키를 찾아 사용합니다.
- 등록된 PPK와 같은 폴더의 PPK를 먼저 확인하고 재사용합니다. 암호화된 PPK도 찾는 단계에서는 암호를 묻지 않으며, 실제 서명 시 기존 엔진이 필요한 암호를 받습니다.
- 일치하는 OpenSSH·PEM·SSH.com 개인키는 기존 보호된 저장 경로로 등록하고 원본의 암호화 여부와 암호를 유지합니다. 암호화된 외부 형식은 파일명이 대응하는 후보만 확인하므로, 다른 이름의 암호화 키는 먼저 키 관리자에 등록해야 합니다.
- 키 불일치·손상 공개키·잘못된 암호·입력 취소로는 새 키를 등록하지 않습니다. 호스트에는 확인한 개인키 경로를 저장하므로 재접속 시 공개키 파일을 다시 찾거나 키를 중복 등록하지 않습니다.

공개키는 사용할 키를 식별하며 실제 인증에는 대응하는 개인키가 필요합니다. 검색 순서와 파일명 예시는 [공개키 파일 선택 안내](../public-key-selection.md)를 따릅니다.

## 검증과 제한

- Linux Python 회귀 검사 54개를 통과했습니다. 공개키 관련 14개 검사는 실제 PuTTY 파서·암호 라이브러리와 제품의 검색·등록 결정 로직을 실행합니다. Windows 경로·대화상자·ACL 작성 부분은 테스트 어댑터로 대체한 검사입니다.
- Windows 앱과 테스트 EXE는 Linux에서 교차 빌드합니다. 단일 EXE ZIP, x64 시스템 DLL 의존성, 내장 폰트·아이콘·라이선스, 해시와 소스·도구 출처의 배포 검증 결과는 [manifest](../../release/1.2.18/manifest.json)에 기록합니다.
- Linux 환경이므로 Windows 실제 SSH 서명·SFTP·UI·암호 입력창·ACL·CTest와 NGS 실기 검사는 미실행입니다. Windows에서 `node tests/ssh/key-import-integration.cjs`, `node tests/ssh/integration.cjs`, `node tests/ssh/sftp-integration.cjs` 및 CTest 실행과 화면 캡처 확인이 필요합니다.
- macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
