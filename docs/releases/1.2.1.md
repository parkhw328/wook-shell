# 1.2.1 — SFTP 권한 오류 후 작업 복구

## 변경 사항

- Windows SFTP 다운로드에서 서버가 파일 열기를 `Permission denied`로 거부하면 연결을 유지합니다. 이전에는 모든 작업 오류에서 연결을 종료하고 원격 작업 버튼을 비활성화해 탭이 멈춘 것처럼 보였습니다. 이제 오류를 확인한 뒤 같은 탭에서 다른 파일을 다운로드하거나 폴더를 이동할 수 있습니다.
- 로컬 임시 파일 생성 실패처럼 연결을 손상시키지 않는 오류도 연결을 유지합니다. 실패한 다운로드는 기존 대상 파일을 보존하며 로컬 임시 파일을 정리합니다.
- 여러 읽기 요청이 진행 중인 상태에서 실패하면 남은 응답을 재사용하지 않도록 연결을 종료합니다. **Refresh** 또는 파일 목록의 **F5**로 같은 탭에서 재연결할 수 있습니다. 연결 실패·취소 후에도 새로고침을 사용할 수 있습니다.
- 읽기 도중 서버가 보낸 권한 오류를 일반적인 파일 변경 메시지로 덮어쓰지 않고 원인을 표시합니다.
- README를 기능·다운로드·빠른 사용법 중심으로 정리하고 상세 사용법과 개발 절차를 분리했습니다. `AGENTS.md`와 `rules/development.md`에 PC 간 공통 규칙과 문서 관리 기준을 명시했습니다.

## 검증과 제한

- Linux 호스트에서 SFTP 코덱 테스트 **155개 검사** 통과. OPEN 거부 후 연결 재사용, READ 거부 메시지 보존과 손상된 파이프라인 재사용 차단을 포함합니다. 수정 전에는 READ 권한 오류 메시지 보존 검사가 실패하는 것을 확인했습니다.
- Python 도구 회귀 테스트 **16개** 통과.
- Windows x64 앱과 테스트 EXE 교차 빌드 및 단일 EXE ZIP·내장 폰트/라이선스/아이콘·시스템 DLL 의존성 정적 검사 통과.
- Windows 전용 `node tests/ssh/sftp-error-integration.cjs`를 추가했습니다. 독립 루프백 서버의 OPEN/READ 권한 거부, 버튼 활성 상태, 다음 다운로드, F5 재연결, 임시 파일 정리와 바이트 일치를 검사합니다. 기존 SFTP 통합 테스트에도 오류 후 기존 파일 보존 검사를 추가했습니다.
- **Windows 실행·UI·실제 SSH 통합 테스트와 스크린샷 확인은 이 Linux PC에서 실행하지 않았습니다.** 테스트 EXE 컴파일을 Windows 실행 통과로 표시하지 않습니다. NGS 실기 검증도 미실행입니다.
- 추가 ASan/UBSan 검사는 호스트의 `libasan` 런타임 부재로 링크하지 못했습니다. 일반 호스트 코덱 검사는 통과했습니다.
- macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
