# wShell 0.5.0

Created by **Hyunwook Park**.

## Changes

- Windows now opens CMD and PowerShell in independent ConPTY tabs. CMD is the default (`Ctrl+Shift+L`). Local tabs support duplication, switching and clean shutdown.
- Added a native macOS 13+ AppKit app for Apple Silicon and Intel: SSH, local login shell, tabs, saved hosts, True Color, Flexoki Dark and embedded JetBrains Mono.
- macOS SSH uses the system OpenSSH client with a separate configuration and host-key store. Saved passwords use the login Keychain and are never exported.
- Home cards use consistent spacing and full-width actions. Removed trailing dots from Connection settings and Tools. About credits Hyunwook Park.
- Authentication explicitly distinguishes Password and Public key authentication. Key-pair guidance and actionable authentication errors explain where to use public and private keys. The Windows host editor can open the native key manager and fill in its saved key path.
- A single `VERSION` controls app and package metadata. Downloads are organized under `dist/0.5.0/windows-x64/` and `dist/0.5.0/macos-universal/`, with SHA-256 checksums.

## Downloads and data

- Windows x64: `wshell-0.5.0-windows-x64.zip`, containing only `wShell.exe`.
- macOS Universal: `wshell-0.5.0-macos-universal.zip`, containing `wShell.app`.
- Windows settings stay in `%LOCALAPPDATA%\wShell`; macOS uses `~/Library/Application Support/wShell`.
- **Export / Import does not transfer passwords, encrypted password records, or private-key files.** Re-enter passwords and select private keys after moving settings.

## Platform limits

Windows retains the PuTTY engine's SSH, Serial, Telnet, Rlogin, Raw TCP and advanced settings. This macOS release supports SSH and local terminals; PuTTY-specific protocols and advanced settings are not ported.

Windows private keys use PPK, with OpenSSH/PEM import through the native key manager. macOS uses OpenSSH private keys and the OS key generator. Host lists are portable; host trust must be reviewed again when switching SSH engines.

Windows is unsigned. The macOS bundle is ad-hoc signed and has not undergone Apple Developer ID signing or notarization, so Gatekeeper may require approval on first launch.

## Validation

The release workflow builds both platforms and verifies architecture, embedded assets and package contents. Regression tests cover Windows core/settings/credentials, actual local CMD and PowerShell, SSH public-key/password authentication, tab lifecycle and native UI. macOS tests cover storage and backup validation, Keychain binding, local PTY input and exit, separate tab processes, terminal resize and real OpenSSH key/password connections against a loopback fixture.

Hardware serial devices, enterprise GSSAPI, proxy/X11 configurations and notarized macOS distribution require separate environment-specific validation.
