# 1.1.0 — 탭 분리와 SFTP 파일 드래그앤드롭

## 변경 사항

- 탭을 창 밖으로 끌어 놓거나 탭 메뉴의 **Move to new window**를 선택하면 별도 창으로 분리합니다. 기존 터미널 프로세스·연결·셸 상태를 유지하며 다른 창의 탭 줄로 끌어서 다시 합칠 수 있습니다.
- 창마다 입력·단축키·종료를 처리합니다. 원래 창을 닫아도 분리된 창은 계속 실행되며, 새 실행 요청도 남아 있는 창으로 전달됩니다. 창 사이 이동 시 입력 동기화를 해제하고 임시 세션 설정 이름이 겹치지 않도록 처리합니다.
- 탐색기 → SFTP REMOTE 업로드, SFTP LOCAL ↔ REMOTE 전송, 원격 파일 → 탐색기 다운로드를 지원합니다. 복사 방식이며 원본을 삭제하지 않습니다.
- 원격 파일은 Windows 가상 파일 형식과 스트림으로 제공합니다. 임시 디스크 공간을 사용하며 탐색기가 스트림을 사용하는 동안 파일을 유지하고 이후 정리합니다. 드래그 전송 취소·파일 이름 충돌·기존 덮어쓰기 확인을 처리합니다.
- 폴더가 포함된 선택은 전체 전송을 중단하고 “폴더는 다운로드하거나 업로드할 수 없습니다” 안내를 표시합니다. 링크·정션은 따라가지 않습니다.
- 연결 준비·종료 중인 터미널과 전송 중인 SFTP 탭은 창 이동을 잠시 제한합니다.

## 검증과 제한

- Windows x64 로컬 빌드 및 CTest 4종(핵심 기능, IME, SFTP 코덱, 실행 요청 전달)을 통과했습니다.
- 새 드래그 통합 검사 32개를 통과했습니다. 실제 로컬 셸의 상태 유지·창 분리/합치기·원래 창 종료 후 실행, 실제 루프백 SFTP의 업로드/다운로드 바이트 일치, 한글 파일명, 폴더 안내, 드래그 취소, 스트림 수명을 검사했습니다.
- 기존 SFTP 통합 검사에서 목록·UTF-8·빈 파일·이름 변경·폴더 생성/삭제·덮어쓰기 거절·취소를 검증했습니다. Python 회귀 검사는 13개 중 12개 통과, 환경 조건에 따른 1개 제외입니다.
- 단일 EXE ZIP, SHA-256, PE 내장 리소스 및 시스템 DLL 의존성을 검증합니다. 배포 manifest는 실제 소스 커밋과 검증 범위를 기록합니다.
- **전체 UI 회귀 검사는 완료되지 않았습니다.** 최종 실행은 다른 앱이 테스트 창을 가려 실제 마우스 입력 검사(phase 34)에서 중단됐습니다. 초기 스크롤바 픽셀 검사 실패는 단독 검사에서 통과했으며, 전송 속도 관찰 검사의 타이밍 문제는 루프백 서버 응답 지연을 고정해 보완했습니다.
- 탭 분리는 Win32 마우스 메시지, 합치기는 세션 이동 경로, 파일 드롭은 OLE 데이터 수신기로 자동 검사했습니다. **실제 탐색기 마우스 드롭·창 사이 드롭 위치 판정·다중 모니터 배율·NGS는 수동 미검증**입니다.
- macOS·iPad 빌드 및 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
