# wShell 1.2.25 — 여러 탭에서 새 SSH·SFTP 연결이 대기하던 문제 수정

여러 셸 탭을 열어 둔 상태에서 SSH·SFTP 연결을 추가하면 호스트 키 확인창이나 연결 오류 창이 가려져 새 연결이 계속 대기하는 것처럼 보이던 문제를 수정했습니다.

이제 확인창은 연결을 요청한 탭이 있는 wShell 창 위에 표시됩니다. 확인을 기다리는 동안에도 다른 탭에서 입력하거나 새 연결을 열 수 있습니다. 확인창이 여러 개 열리면 각 선택은 해당 연결에만 적용됩니다. 서버가 SFTP 연결을 거부하면 같은 탭에서 오류를 확인하고 **Reconnect (F5)**로 다시 연결할 수 있습니다.

## 검증

- Wine 8.0에서 배포 EXE로 같은 서버·계정에 SSH 8개와 SFTP 8개를 동시에 연결했습니다. 16개 연결이 유지됐고 SFTP 탭 8개 모두 파일 목록을 읽었습니다.
- 서로 다른 주소와 호스트 키를 가진 루프백 서버 세 대로도 배포 EXE를 검증했습니다. 첫 서버의 셸을 열어 둔 상태에서 두 번째 서버의 SSH와 세 번째 서버의 SFTP 확인창이 함께 표시됐고, 승인 후 세 연결이 모두 유지됐습니다.
- Wine 통합 검사에서 기존 셸로 입력이 전달되는 동안 다른 연결의 확인창 두 개가 계속 열려 있는지, SFTP를 먼저 승인해 목록을 읽을 수 있는지, 서버가 SFTP를 거부한 뒤 같은 탭에서 재접속할 수 있는지 확인했습니다. SFTP 일회용 인증 코드 입력과 취소, 다른 창의 포커스 유지도 확인했습니다.
- Linux에서 Windows x64 교차 빌드와 Python 회귀 테스트 60개가 통과했습니다. EXE의 파일·제품 버전은 `1.2.25.0`이며 ZIP에는 배포 EXE와 바이트가 같은 `wShell.exe` 한 개가 들어 있습니다. 내장 리소스, DLL 의존성, SHA-256을 확인했습니다. [빌드 정보와 해시](../../release/1.2.25/manifest.json)
- Wine에서 SFTP 코덱 검사 340개가 통과했습니다. 전체 `core-tests`는 이전 버전과 같이 현재 사용자의 DPAPI 비밀번호 복호화 검사에서 중단됐습니다. Windows 실기와 NGS 환경에서의 실행은 미검증이며 배포 EXE는 미서명입니다.
