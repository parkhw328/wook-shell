# 1.2.5 — 전체 화면 앱 클릭과 SFTP 경로 입력 포커스

## 변경 사항

- Codex의 `Back to bottom`처럼 전체 화면 앱이 제공하는 버튼을 클릭할 수 있습니다. 1.2.4의 휠 전달을 클릭·버튼 해제·드래그·포인터 이동까지 확장했습니다. 마우스 보고를 요청한 대체 화면의 최신 위치에만 적용합니다.
- 전체 화면 앱에서 텍스트를 복사하려면 **Shift+드래그**, 붙여넣으려면 **Shift+우클릭**을 사용하세요. **Shift+휠**은 터미널 기록을 스크롤합니다. 일반 셸에서는 기존 드래그 복사·우클릭 붙여넣기를 유지합니다.
- 명시적인 마우스 보고 차단, 일반 화면 복귀, 터미널 기록을 보는 중의 로컬 동작을 유지합니다. 설정 화면의 안내도 갱신했습니다.
- SFTP Local/Remote Location에서 Enter로 경로 이동이 성공하면 해당 파일 목록으로 포커스를 옮겨 경로 입력 커서가 사라집니다.
- 원격 경로 이동 실패 시 입력칸으로 포커스를 복원해 경로를 바로 수정할 수 있습니다. 응답 대기 중 다른 목록이나 창으로 이동한 경우 포커스를 빼앗지 않습니다.

## 검증과 제한

- Windows x64 릴리스 빌드, CTest 4개(launch-relay, sftp-codec, core, ime), 단일 EXE ZIP·내장 리소스·시스템 DLL 의존성·해시 검증을 수행했습니다. 사용 중인 개발용 EXE를 종료하지 않고 별도 빌드 경로를 사용했습니다.
- Python 도구 검사: 13개 실행, 호스트 C 컴파일러가 필요한 검사 1개 건너뜀.
- 스크롤 4종(64/64/57/57개 조건)과 마우스 4종(각 62개 조건)을 통과했습니다. 기본/출력 추적/명시적 보고 차단/보고 미요청, 일반/대체 화면과 복사 우선 설정 양쪽 조합을 검사했습니다. `Back to bottom` 위치의 클릭·해제와 앱 화면 복귀, Shift 복사·붙여넣기, 일반 화면 복귀를 확인했습니다.
- SFTP 오류·경로 Enter 검사 71개 조건을 통과했습니다. 로컬·원격 성공 후 목록 포커스, 잘못된 원격 경로의 입력 포커스 보존, 응답 대기 중 다른 목록의 포커스 보존, 권한 오류 복구와 F5 재연결을 검사했습니다. 경로 이동 완료 화면도 확인했습니다.
- 폰트 캐시, 메시지·확인창(253개 조건), 실행 인자, 개인키 인증 검사를 통과했습니다.
- 전체 SSH/UI 통합 검사는 phase 34의 실제 마우스 입력 대상 확인(`Native click must hit the test window, never another application`)에서 중단되어 미완료입니다. 입력 대상 확인 실패를 통과로 처리하지 않았습니다. 잠기지 않은 데스크톱에서 입력 간섭 없이 재검증해야 합니다.
- 스크롤 회귀 검사의 OS 커서 좌표가 비활성 터미널에서 갱신되지 않는 경우를 보완했습니다. 초기 화면의 셀 위치로 버튼 좌표를 계산하고 단계별 시간 제한을 적용했습니다. 최종 스크롤 검사는 보강된 테스트 커밋 `1978baa`에서 실행했으며, 배포 앱의 소스는 `724070b`입니다.
- 휠·클릭·포커스 전용 검사는 Win32 메시지와 실제 루프백 SSH를 사용합니다. 모든 앱이나 실제 마우스 장치의 물리 입력을 검증한 것은 아닙니다. 실제 Codex 세션의 새 버전 클릭 동작은 별도 확인이 필요합니다.
- NGS 실기 검사, macOS·iPad 빌드와 GitHub Actions는 실행하지 않았습니다. Windows EXE는 미서명입니다.
