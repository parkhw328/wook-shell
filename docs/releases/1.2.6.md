# 1.2.6 — SFTP 다운로드 요청 정체 수정

## 원인과 변경 사항

- tar.gz 다운로드 속도가 2~15MB/s로 변한다는 보고를 바탕으로 다운로드 경로를 점검했습니다. SFTP 연결에 PuTTY의 파일 전송용 단일 채널 설정이 빠져 있어 초기 SSH 수신 윈도가 터미널용 16KB로 시작하고, 이후 윈도 조정에 의존하는 경로를 확인했습니다. PuTTY PSFTP와 같은 `CONF_ssh_simple` 설정을 적용하고 기존 파이프 backlog 제어를 유지합니다.
- 다운로드는 먼저 요청한 블록이 도착할 때까지 뒤쪽 응답을 메모리에 보관했습니다. 늦은 블록 하나가 최대 64개 요청의 저장·후속 요청 보충을 막아 진행률과 실제 요청이 함께 정체되는 조건을 재현했습니다.
- Windows는 검증한 응답을 임시 파일의 해당 오프셋에 즉시 기록하고 빈 요청 자리를 보충합니다. 짧은 응답도 받은 바이트를 먼저 기록한 뒤 나머지만 요청합니다. 진행률은 파일에 기록한 총 바이트이며, 속도 표시의 평균 구간을 늘리는 방식으로 정체를 숨기지 않습니다.
- 최대 64개 요청, 긴 서버 핸들의 요청 바이트 제한, 응답 ID·길이 검증, 취소·실패 시 기존 파일 보호를 유지합니다. 모든 데이터 저장·flush·서버 파일 닫기가 성공한 뒤에만 임시 파일을 목적 파일로 옮깁니다.
- 공통 C 코덱에 위치 지정 출력 API를 추가했습니다. 기존 순차 출력 API와 macOS 호출 경로는 보존하며 macOS·iPad 빌드는 수행하지 않습니다.

## 재현과 검증

`tests/test_sftp_pipeline.py`는 압축이 잘 되지 않는 결정적 데이터를 실제 tar.gz로 만들고, 요청에 대응하는 SFTP 응답만 반환하는 가상 서버로 코덱을 실행합니다. 파일 크기는 8,391,399 bytes, 기본 응답 지연은 40ms이며 2MB마다 첫 블록을 300ms 지연시킵니다. 1.2.5 코덱과 수정본을 같은 데이터로 비교했습니다.

| 최대 응답 크기 | 기존 완료 시각 → 수정 후 | 최초 진행 시각 → 수정 후 |
| --- | --- | --- |
| 32,768 bytes | 1,500 → 460ms | 300 → 40ms |
| 17,003 bytes | 1,660 → 620ms | 340 → 40ms |

표는 **응답 지연 모델의 가상 시간**입니다. Windows·SSH·디스크를 포함한 실측 처리량이나 사용자 서버의 개선율이 아닙니다. 네 조건 모두 원본과 다운로드의 SHA-256이 일치했습니다. 사용자 서버와 해당 파일에는 직접 접근하지 않았으므로 보고된 속도 변동의 모든 원인을 확인한 것은 아닙니다.

- Linux 호스트에서 공통 코덱 회귀 검사 340개 통과: 두 윈도보다 늦게 도착한 첫 블록, 요청 보충, 짧은 응답·부분 로컬 쓰기, 긴 핸들, 순서 변경, 손상·중복 응답, 쓰기 실패, EOF, 취소, 기존 순차 출력 경로.
- Python 회귀 검사 18개 통과. 새 tar.gz 지연 모델 검사 2개를 포함합니다.
- ASan/UBSan을 함께 적용한 코덱 검사도 시도했으나 호스트의 `libasan.so.6.0.0` 부재로 링크하지 못해 실행하지 않았습니다. 일반 호스트 코덱 검사는 경고를 오류로 처리하여 빌드·실행했습니다.
- Windows x64 교차 빌드와 테스트 EXE 컴파일, 단일 EXE ZIP·내장 리소스·시스템 DLL 의존성·SHA-256 정적 검사 통과.
- Windows SFTP 통합 검사에 초기 수신 윈도 검증을 추가하고 벤치마크에 일부 블록 지연과 최장 진행 정체 시간 측정을 추가했습니다. JavaScript 구문 검사는 통과했습니다.
- Windows 실행 환경이 없어 CTest·SFTP/SSH/UI·IME·DPAPI·NGS 실기 검사는 실행하지 않았습니다. macOS·iPad 빌드와 GitHub Actions도 실행하지 않았습니다. manifest에 Linux 교차 빌드와 Windows 실행 미검증 상태를 기록합니다.

Windows에서는 [개발 안내](../development.md)에 따라 빌드한 뒤 `node tests/ssh/sftp-integration.cjs`, `node tests/ssh/sftp-error-integration.cjs`, `node tests/ssh/sftp-benchmark.cjs`와 CTest를 실행해야 합니다. 사용자 서버의 같은 파일로 비교할 때는 기존 버전과 새 버전의 실제 완료 시간도 함께 확인하세요.
