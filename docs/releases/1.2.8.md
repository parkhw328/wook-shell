# 1.2.8 — CLI 화면의 일반 드래그 복사 복원

## 원인과 변경 사항

1.2.5에서 대체 화면의 원격 앱 버튼을 클릭하도록 확장한 처리가 드래그까지 앱으로 전달하여, 복사 우선 설정을 켠 상태에서도 일반 드래그로 복사할 수 없었습니다.

- 기본 `Prefer mouse copy and paste` 설정에서는 일반 셸과 대체 화면 모두 Shift 없이 드래그하여 텍스트를 선택하고 자동 복사합니다. 우클릭 붙여넣기와 더블·트리플 클릭 선택도 기존 로컬 처리로 돌아갑니다.
- 대체 화면의 앱 내부 휠 스크롤은 유지합니다. 포인터 이동과 버튼·드래그는 앱에 전달하지 않아 선택 중 좌표 보고가 섞이지 않습니다. Shift+휠은 터미널 기록을 스크롤합니다.
- 원격 앱 버튼이나 드래그 기능이 필요하면 `Settings → Selection & clipboard → Prefer mouse copy and paste`를 끄고 적용하세요. 이 경우 기존 원격 마우스 처리와 Shift 복사 우회를 사용합니다. 사용자가 저장한 명시적 설정은 덮어쓰지 않습니다.
- 1.2.7의 종료 시 남은 마우스 보고 정리와 WinSCP 형식 SFTP 접속은 유지합니다.

## 검증

- Python 회귀 검사 24개 통과. 새 검사 4개는 패치된 PuTTY 입력 분기 코드를 호스트 C 컴파일러로 실행하여 일반·대체 화면의 버튼/이동 차단, 네 방향 휠 전달, Shift·명시적 보고 차단·기록 위치, 설정 변경과 명시적 해제를 확인합니다.
- Windows 마우스 통합 검사는 대체 화면에서도 일반 드래그의 실제 클립보드 문자열과 한글 우클릭 붙여넣기를 확인하도록 변경했습니다. 스크롤 검사는 휠만 서버에 도착하고 일반 클릭은 도착하지 않아야 합니다. 두 JavaScript 파일의 구문 검사를 통과했습니다.
- Windows x64 교차 빌드·테스트 EXE 컴파일 및 단일 EXE ZIP·내장 리소스·시스템 DLL·SHA-256 정적 검사를 수행합니다. manifest에 커밋된 소스와 Linux 교차 빌드 출처를 기록합니다.
- 이 환경에는 Windows 데스크톱이 없어 실제 클립보드·SSH/UI·IME·DPAPI·NGS 및 실제 Codex 드래그 검사는 실행하지 않았습니다. 1.2.7에 대한 이전 사용자 확인을 이번 수정의 검증 결과로 재사용하지 않습니다. macOS·iPad 빌드와 GitHub Actions도 실행하지 않습니다.

Windows 후속 검사는 [개발 안내](../development.md)에 따라 마우스 기본·`--application-mouse`·`--alternate-screen`·두 옵션 조합 및 스크롤 기본·`--follow-output`·`--block-mouse`·`--no-mouse` 모드를 실행하세요.
