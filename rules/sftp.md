# SFTP 개발 규칙

- 전용 탭에 로컬·원격 목록을 나란히 표시하고 `ui.hpp` / `Theme`의 글꼴과 주황색 강조를 따른다.
- Windows의 업로드 `>`·다운로드 `<` 버튼은 두 파일 목록 사이에 둔다. 방향을 툴팁·접근성 이름·레이블로 설명하고, 연결 및 원본 파일 선택 상태에 따라 활성화한다. 전송 중에는 양쪽 버튼을 비활성화하며 최소 창 크기에서도 목록·버튼이 겹치지 않게 한다.
- `Show hidden files` 체크박스는 새 탭에서 기본 해제한다. 로컬·원격 dotfile/folder와 로컬 OS 숨김 속성을 반영한다. 필터링 후 선택 인덱스가 다른 파일을 가리키지 않도록 검증한다.
- 공통 SFTP v3 코덱은 `mac/Sources/CSFTP/`에 둔다. Windows CMake와 macOS SwiftPM이 같은 C 코드를 빌드한다. SSH 암호화는 기존 플랫폼 엔진을 재사용한다.
- 저장 호스트·호스트 키 신뢰·현재 사용자 암호 저장 정책을 재사용한다. 비밀번호를 인수·환경변수·디스크 임시 파일로 전달하지 않는다.
- SFTP는 독립 연결이며 PTY·포트 전달·세션 파일 로깅을 사용하지 않는다. Windows 내부 작업 프로세스에는 필요한 파이프만 상속하고 작업 Job으로 수명을 관리한다.
- 네트워크·전송은 작업 스레드에서 처리한다. 화면 접근은 UI 스레드에서만 수행한다. 취소와 탭 닫기는 자신이 시작한 연결만 종료한다.
- 서버 프레임·요청 ID·문자열 길이·파일명을 검증한다. 원격 이름으로 로컬 경로를 벗어나거나 장치/대체 스트림을 만들지 않는다. 링크를 따라 재귀 탐색하지 않는다.
- 같은 이름의 파일은 구체적인 대상 목록을 확인한 뒤 교체한다. 새 파일은 배타적으로 생성하고, 임시 파일에 전송을 완료한 후 옮긴다. 원격 덮어쓰기는 POSIX rename 확장이 없으면 거부한다.
- 전송 실패 시 기존 파일을 먼저 삭제하지 않는다. 중단 업로드의 원격 임시 파일이 남을 수 있음을 표시하고, 미지원 기능은 `docs/sftp.md`에 명시한다.
- 독립 루프백 서버로 실제 바이트 일치·UTF-8 이름·짧은 읽기·취소·키/암호 인증을 검증한다. 테스트는 `build/` 아래 격리된 폴더만 사용한다.
