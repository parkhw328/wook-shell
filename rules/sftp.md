# SFTP 개발 규칙

- 전용 탭에 로컬·원격 목록을 나란히 표시하고 `ui.hpp` / `Theme`의 글꼴과 주황색 강조를 따른다.
- Windows의 업로드 `>`·다운로드 `<` 버튼은 두 파일 목록 사이에 둔다. 방향을 툴팁·접근성 이름·레이블로 설명하고, 연결 및 원본 파일 선택 상태에 따라 활성화한다. 전송 중에는 양쪽 버튼을 비활성화하며 최소 창 크기에서도 목록·버튼이 겹치지 않게 한다.
- `Show hidden files` 체크박스는 새 탭에서 기본 해제한다. 로컬·원격 dotfile/folder와 로컬 OS 숨김 속성을 반영한다. 필터링 후 선택 인덱스가 다른 파일을 가리키지 않도록 검증한다.
- 공통 SFTP v3 코덱은 `mac/Sources/CSFTP/`에 둔다. Windows CMake와 macOS SwiftPM이 같은 C 코드를 빌드한다. SSH 암호화는 기존 플랫폼 엔진을 재사용한다.
- 저장 호스트·호스트 키 신뢰·현재 사용자 암호 저장 정책을 재사용한다. 비밀번호를 인수·환경변수·디스크 임시 파일로 전달하지 않는다.
- Windows 인증 입력창은 별도 작업 프로세스에서 열리므로, 전경 인증창을 닫기 전에 원래 작업 공간으로 전경을 넘긴다. 같은 프로세스의 모달 소유자는 창 파괴 전에 다시 활성화 가능하게 만들고 기존 입력 포커스를 복원한다. 사용자가 다른 창으로 전환한 경우 포커스를 빼앗지 않는다. `node tests/ssh/sftp-auth-integration.cjs`로 다중 OTP의 Enter·Esc와 전경 복귀를 검사한다.
- SFTP는 독립 연결이며 PTY·포트 전달·세션 파일 로깅을 사용하지 않는다. Windows 내부 작업 프로세스에는 필요한 파이프만 상속하고 작업 Job으로 수명을 관리한다.
- 네트워크·전송은 작업 스레드에서 처리한다. 화면 접근은 UI 스레드에서만 수행한다. 취소와 탭 닫기는 자신이 시작한 연결만 종료한다.
- Windows 파일 목록은 전송 중에도 활성 상태로 두어 어두운 배경과 스크롤을 유지한다. 작업 버튼과 폴더 이동은 busy 검사로 차단하고, 전송 시작 시 복사한 대상 목록을 사용한다. 업로드·다운로드 중 빈 목록 영역의 실제 배경색과 KB/s 표시를 회귀 검사한다.
- Windows 파일 목록의 F2·Delete·F5는 기존 Rename·Delete·Refresh 동작과 버튼 활성 조건을 재사용한다. 이름 변경·삭제는 키 알림을 보낸 목록의 선택 항목에 적용하고 삭제 확인을 유지한다. Ctrl·Shift·Alt 조합과 경로 입력은 가로채지 않으며, 대화상자가 닫히면 원래 목록으로 포커스를 돌려준다.
- 서버 프레임·요청 ID·문자열 길이·파일명을 검증한다. 원격 이름으로 로컬 경로를 벗어나거나 장치/대체 스트림을 만들지 않는다. 링크를 따라 재귀 탐색하지 않는다.
- 같은 이름의 파일은 구체적인 대상 목록을 확인한 뒤 교체한다. 새 파일은 배타적으로 생성하고, 임시 파일에 전송을 완료한 후 옮긴다. 원격 덮어쓰기는 POSIX rename 확장이 없으면 거부한다.
- 전송 실패 시 기존 파일을 먼저 삭제하지 않는다. 중단 업로드의 원격 임시 파일이 남을 수 있음을 표시하고, 미지원 기능은 `docs/sftp.md`에 명시한다.
- 독립 루프백 서버로 실제 바이트 일치·UTF-8 이름·짧은 읽기·취소·키/암호 인증을 검증한다. 테스트는 `build/` 아래 격리된 폴더만 사용한다.

- 권한 거부나 로컬 파일 생성 실패처럼 프로토콜 상태가 정상인 오류는 메시지를 표시하고 연결·목록·다음 작업을 유지한다. 진행 중 READ/WRITE 응답이 남거나 프로토콜·전송이 손상되면 해당 연결을 종료하되, 같은 탭의 Refresh/F5로 다시 연결할 수 있어야 한다. 실패만으로 전체 작업 버튼을 영구 비활성화하지 않는다.
- 서버의 Permission denied 원인을 일반적인 파일 변경 오류로 덮어쓰지 않는다. `node tests/ssh/sftp-error-integration.cjs`로 OPEN 거부 후 다른 파일 다운로드, READ 거부 후 F5 재연결, 임시 파일 정리와 UI 응답을 검증한다.

- Local/Remote 경로 입력칸의 Enter는 포커스가 있는 입력칸에 대응하는 Go만 실행한다. 기존 Go 명령과 활성 조건을 재사용하며 작업 중·드래그 중·비활성 상태에서는 이동하지 않는다. 키 반복으로 중복 실행하지 않고, Tab 등 기존 편집·포커스 이동 키는 유지한다.
