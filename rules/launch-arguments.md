# Windows 실행 인자

- 주소를 인자로 주면 SSH 호스트를 등록하고 즉시 접속한다. PuTTY 형식 `-ssh`, `-P`, `-l`, `-pw`와 `--host`, `--port`, `--user`, `--password`, `--name`, `--password-stdin`을 지원한다. 전체 PuTTY CLI 호환으로 안내하지 않는다.
- 주소·포트·사용자가 같은 SSH 호스트를 재사용하고 사용자 지정 이름·별칭·폰트·고급 옵션·저장 암호를 보존한다. DNS 조회 결과나 IP 별칭만으로 두 호스트를 합치지 않는다.
- `--name`이 다른 주소·포트·계정의 이름과 충돌하면 오류를 표시하고 아무 호스트도 덮어쓰지 않는다. 중복 옵션·알 수 없는 옵션·잘못된 포트·누락 값은 접속 전에 거부한다. 오류에 인자 값이나 전체 명령줄을 표시하지 않는다.
- 전달한 암호는 해당 접속의 SSH password 인증에 한 번만 공급한다. 현재 사용자 DPAPI로 암호화한 임시 레코드의 식별자만 자식 프로세스에 전달하며, 소비 시 삭제한다. 미사용 레코드는 탭 정리 시 삭제한다. 비정상 강제 종료 후 남은 암호문은 재사용하거나 목록·백업에 포함하지 않는다.
- 실행 인자가 기존 저장 암호를 변경하거나 암호 저장 동의를 대신하지 않는다. 재접속·복제에는 일회용 암호를 다시 공급하지 않는다. 암호를 계속 보관하려면 기존 Edit의 명시적 저장 기능을 사용한다.
- 호스트 신뢰 확인·불일치 차단과 키 암호·OTP의 수동 입력 규칙을 유지한다. 인자 접속이 호스트 키 검사를 우회하지 않는다.
- `--password-stdin`은 UTF-8 파이프의 첫 줄 또는 EOF를 읽으며 끝의 CR/LF만 제거한다. 비밀번호의 공백·따옴표·유니코드는 그대로 유지한다. 셸을 거치지 않고 프로세스를 생성한다.
- `-pw`는 최초 실행 프로세스 목록·호출한 셸 기록에 노출될 수 있음을 문서화한다. 앱 내부에서 자식 인수나 로그로 재전달하지 않는 것과 구분한다.
- 파싱·충돌·DPAPI 범위·일회용 소비는 `tests/launch_test.inc`, 배포 EXE의 실제 SSH 접속·비밀 없는 자식 인수는 `tests/ssh/launch-integration.cjs`로 검증한다. 테스트는 격리 저장소와 루프백만 사용한다.
