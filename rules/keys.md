# Windows 개인키 등록

- 확장자가 아니라 파일 내용으로 개인키 형식을 판별한다. PPK, OpenSSH 개인키, 기존 PEM RSA/DSA/EC와 SSH.com 형식의 읽기·변환은 내장 PuTTY 함수를 사용한다. 암호 연산이나 키 파서를 재구현하지 않는다.
- 호스트 저장·접속과 Host Settings 적용에서 OpenSSH/PEM 개인키를 사용할 수 있어야 한다. 원본은 수정하지 않고 `%LOCALAPPDATA%\wShell\keys`에 PPK v3 사본을 등록한다. `WOOK_DATA_DIR` 지정 시 그 아래로 격리한다.
- 가져온 키의 암호화 여부와 암호를 유지한다. 키 암호는 별도로 저장하거나 프로세스 인수·환경변수로 전달하지 않는다. 암호와 복호화한 개인키 버퍼는 사용 후 정리한다.
- 등록 파일과 임시 파일은 현재 Windows 사용자와 SYSTEM만 접근할 수 있는 보호된 ACL로 작성하고 원자적으로 게시한다. 같은 이름의 키를 덮어쓰지 않는다. 등록된 키는 재접속할 때 다시 변환하지 않는다.
- 키 관리자는 등록된 키 목록과 호스트에 연결하는 `Use key`를 제공한다. 공개키만 있는 파일은 개인키로 등록하지 않고 대응하는 개인키가 필요하다고 안내한다.
- 등록된 개인키는 설정 백업·배포·커밋에서 제외한다. 테스트는 생성한 임시 키와 루프백 SSH 서버로만 서명을 검증한다. 사용자가 제공한 키는 명시적으로 지정한 파일의 읽기·형식 확인에만 사용하며 원격 서버 인증 테스트에 사용하지 않는다.
- `node tests/ssh/key-import-integration.cjs`로 PEM RSA, 암호화한 PEM RSA·OpenSSH Ed25519, 잘못된 암호·공개키·손상 파일 거부, 보호된 파일 권한, 재사용과 독립 SSH 서버의 실제 서명을 검증한다.
