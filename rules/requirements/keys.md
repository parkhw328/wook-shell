# Windows SSH 공개키 선택·개인키 등록 요구사항

- 확장자가 아니라 파일 내용으로 개인키 형식을 판별한다. PPK, OpenSSH 개인키, 기존 PEM RSA/DSA/EC와 SSH.com 형식의 읽기·변환은 내장 PuTTY 함수를 사용한다. 암호 연산이나 키 파서를 재구현하지 않는다.
- 호스트 저장·접속과 Host Settings 적용에서 OpenSSH/PEM 개인키를 사용할 수 있어야 한다. 원본은 수정하지 않고 `%LOCALAPPDATA%\wShell\keys`에 PPK v3 사본을 등록한다. `WOOK_DATA_DIR` 지정 시 그 아래로 격리한다.
- 가져온 키의 암호화 여부와 암호를 유지한다. 키 암호는 별도로 저장하거나 프로세스 인수·환경변수로 전달하지 않는다. 암호와 복호화한 개인키 버퍼는 사용 후 정리한다.
- 등록 파일과 임시 파일은 현재 Windows 사용자와 SYSTEM만 접근할 수 있는 보호된 ACL로 작성하고 원자적으로 게시한다. 생성 시 보안 속성만 믿지 않고 열린 파일에 권한을 적용한 뒤 상속 차단을 확인하고 개인키를 기록한다. 같은 이름의 키를 덮어쓰지 않는다. 등록된 키는 재접속할 때 다시 변환하지 않는다.
- 키 관리자는 등록된 키 목록과 호스트에 연결하는 `Use key`를 제공한다. 공개키 파일 자체는 개인키로 등록하지 않는다.
- 2026-10-31 사용자 요청에 따라 호스트 저장·접속, Host Settings 적용과 키 관리자에서 OpenSSH/RFC4716 공개키 파일을 선택할 수 있다. 먼저 등록 목록의 PPK, 다음으로 선택 파일과 같은 폴더의 PPK·암호 없는 개인키를 검사한다. 파일명·주석·지문 문자열 대신 PuTTY가 읽고 검증한 SSH 공개키 blob 전체가 일치해야 한다. 하위 폴더는 검색하지 않는다.
- 암호화된 OpenSSH/PEM·SSH.com 후보는 공개키의 마지막 확장자를 뺀 이름 또는 그 이름에 `.ppk`·`.pem`·`.key`·`.openssh`를 붙인 파일에 한해 암호를 받아 비교한다. 예: `id_ed25519.pub`와 `id_ed25519`, `server.pub`와 `server.pem`, `server.pem.pub`와 `server.pem`. 다른 이름의 암호화된 키는 먼저 키 관리자에 등록하도록 안내한다. 무관한 암호화 파일의 암호를 반복 요청하지 않는다.
- 일치하는 PPK는 암호를 풀거나 복사하지 않고 재사용하며 인증 시 기존 엔진이 필요한 암호를 받는다. 외부 형식은 실제 개인키를 읽어 공개키 일치를 확인한 다음 기존 보호된 등록 경로로 저장한다. 취소·잘못된 암호·불일치·손상 공개키는 등록이나 접속으로 이어지지 않는다. 호스트에는 확인한 개인키 경로를 저장한다.
- 등록된 개인키는 설정 백업·배포·커밋에서 제외한다. 테스트는 생성한 임시 키와 루프백 SSH 서버로만 서명을 검증한다. 사용자가 제공한 키는 명시적으로 지정한 파일의 읽기·형식 확인에만 사용하며 원격 서버 인증 테스트에 사용하지 않는다.
- `python3 -m unittest discover -s tests -p test_public_key.py -v`는 Linux에서 실제 PuTTY 파서·암호 라이브러리와 제품의 검색·등록 결정 로직을 실행한다. Windows 경로·대화상자·파일 권한 작성은 테스트 어댑터로 대체하며 Windows 검증으로 표시하지 않는다.
- `node tests/ssh/key-import-integration.cjs`로 공개키 선택, PEM RSA·암호화한 PEM RSA/OpenSSH Ed25519의 일치·등록, 잘못된 암호·취소·키 불일치·손상 파일 거부, 보호된 파일 권한, 재사용과 독립 SSH 서버의 실제 서명을 검증한다.
